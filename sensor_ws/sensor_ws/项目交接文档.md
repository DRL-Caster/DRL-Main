# AGV 自主导航系统 — 项目交接文档

欢迎接手此项目。本文档帮助你快速了解项目背景、搭建环境、启动系统，并理解几个关键设计细节。

---

## 一、项目是什么

这是一套基于 **ROS 2 Jazzy** 的工业 AGV（自动导引车）自主导航系统，主要功能：

- 激光雷达 + IMU 传感器采集环境数据
- 使用 slam_toolbox 建图，之后用于自主定位
- 使用 Nav2 实现全自主路径规划和导航
- 通过 **Modbus TCP 协议**（网口）控制 AGV 底盘运动
- 支持键盘手动遥控，可与自动导航模式随时切换

场地地图已保存在 `src/sensor_bringup/maps/`，可直接用于定位和导航，不需要重新建图（除非换了场地）。

## 二、硬件清单

| 设备 | 型号 | 接口 | 原环境默认地址 |
|------|------|------|--------------|
| AGV 底盘 | — | 网线（Modbus TCP） | `192.168.1.254`，端口 `1024` |
| 激光雷达 | LDRobot LD06 | USB 串口 | `/dev/ttyUSB0` |
| IMU | ybimu | USB 串口 | `/dev/ttyUSB1` |

> 这些地址是原开发环境的值，你的环境不一定相同。**不需要改代码**，启动时通过参数覆盖即可（见第四节）。

## 三、环境搭建

### 系统要求

- Ubuntu 24.04
- ROS 2 Jazzy（已安装）
- 需要额外安装的 ROS 包：

```bash
sudo apt install ros-jazzy-slam-toolbox ros-jazzy-nav2-bringup \
  ros-jazzy-imu-filter-madgwick ros-jazzy-robot-localization
```

### 首次构建

```bash
cd ~/sensor_ws    # 进入工作空间目录
source /opt/ros/jazzy/setup.bash
colcon build
source install/setup.bash
```

> 每次修改代码后，需重新执行 `colcon build` 和 `source install/setup.bash`，否则改动不会生效。

## 四、启动系统

### 4.1 仅传感器 + 键盘遥控（最基础，用于验证硬件）

```bash
source /opt/ros/jazzy/setup.bash && source install/setup.bash
ros2 launch sensor_bringup sensor_bringup.launch.py
```

开启 Rviz 可视化：
```bash
ros2 launch sensor_bringup sensor_bringup.launch.py enable_rviz:=true
```

键盘控制方式（终端会打印提示）：

| 按键 | 动作 |
|------|------|
| `w` | 前进 |
| `s` | 后退 |
| `a` | 左转 |
| `d` | 右转 |
| `空格` 或 `x` | 停止 |
| `q` | 退出 |

### 4.2 建图模式（新场地时使用）

```bash
ros2 launch sensor_bringup slam_bringup.launch.py
```

开车把整个场地走一遍，建好图后执行以下命令保存：

```bash
# 保存栅格地图（.pgm 图片 + .yaml 描述文件）
ros2 run nav2_map_server map_saver_cli -f src/sensor_bringup/maps/场地名称

# 保存 SLAM 位姿图（slam_toolbox 内部格式，用于后续定位）
ros2 service call /slam_toolbox/save_map slam_toolbox/srv/SaveMap \
  "{name: {data: 'src/sensor_bringup/maps/场地名称'}}"
```

### 4.3 自主导航模式

```bash
ros2 launch sensor_bringup nav_bringup.launch.py
```

启动后在 Rviz 中用"2D Pose Estimate"给 AGV 设置初始位置，然后用"Nav2 Goal"发送目标点即可。

### 4.4 适配你的硬件环境

如果你的 AGV IP、端口或串口路径与默认值不同，通过参数传入：

```bash
ros2 launch sensor_bringup sensor_bringup.launch.py \
  agv_host:=192.168.x.x \
  agv_port:=1024 \
  imu_port:=/dev/ttyUSB0
```

## 六、几个必须了解的设计细节

### 1. AGV 通信：心跳包问题

AGV 设备会在 TCP 连接上主动发送**心跳包**（以字节 `0xBB` 开头，每帧固定 34 字节）。这是设备的特殊行为，代码里必须在解析 Modbus 响应之前先过滤掉这些帧，否则通信会乱掉。这个逻辑已经在 `agv_control/agv_control/agv_bridge.py` 里实现好了，不要删除。

### 2. 里程计精度有限

AGV 底盘没有轮式编码器，所以系统只能用"发了什么指令"来估算位置（航位推算）。速度常数写死在 `sensor_bringup/sensor_bringup/command_odom.py` 里（前进 0.20 m/s、后退 0.16 m/s、转速 0.75 rad/s）。

如果你用的 AGV 型号或载荷不同，这些数值需要重新标定，否则建出来的地图会变形，导航精度也会下降。

### 3. 手动/自动模式切换

系统支持在运行时切换手动遥控和 Nav2 自动导航，不需要重启。通过 `initial_mode` 参数控制启动时的默认模式：

```bash
# 以自动导航模式启动
ros2 launch sensor_bringup nav_bringup.launch.py initial_mode:=nav
```

当前模式可通过话题查看：
```bash
ros2 topic echo /agv/current_mode
```

## 七、常见问题排查

**AGV 连接失败 / 不动**
- 检查网线是否接好，AGV 是否开机
- 执行 `ping 192.168.1.254`（换成你的 IP）确认网络连通
- 确认防火墙未拦截 1024 端口

**激光雷达没数据（`/scan` 话题为空）**
- 检查 USB 是否识别：`ls /dev/ttyUSB*`
- 串口权限问题：`sudo chmod 666 /dev/ttyUSB0`
- 或把用户加入 dialout 组（永久生效）：`sudo usermod -aG dialout $USER`，然后重新登录

**IMU 串口打不开**
- 同上，检查串口权限
- 可通过参数手动指定：`imu_port:=/dev/ttyUSB1`

**修改代码后没有效果**
- 一定要重新 `colcon build`，然后重新 `source install/setup.bash`

**Nav2 规划了路径但 AGV 不执行**
- 检查当前模式是否为 `nav`：`ros2 topic echo /agv/current_mode`
- 确认 launch 时使用的是 `nav_bringup.launch.py`

## 八、参数调优参考

如果需要调整导航行为，以下是常用参数位置：

| 想调整的内容 | 文件 | 参数名 |
|------------|------|-------|
| AGV 最大速度 | `config/nav2_params.yaml` | `max_vel_x` |
| 到达目标点的位置容差 | `config/nav2_params.yaml` | `xy_goal_tolerance` |
| 到达目标点的角度容差 | `config/nav2_params.yaml` | `yaw_goal_tolerance` |
| 地图分辨率 | `config/slam_toolbox_mapping.yaml` | `resolution` |
| 里程计速度常数 | `sensor_bringup/command_odom.py` | 文件顶部常数 |
